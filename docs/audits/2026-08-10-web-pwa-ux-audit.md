# Web + PWA UX Audit — apps/web against the "10/10" bar

Scope: `apps/web` (React Router v7 framework mode, Cloudflare Workers) and `packages/ui` (Constellation/Horizon design system), against docs/07, docs/15, docs/22, docs/06, and CLAUDE.md rules 5/7/8. Sampled: `home.tsx`, `axis-board.tsx`, `orbit-console.tsx`, `signal-cockpit.tsx`, `scout-radar.tsx`, `north-brief.tsx`, `login.tsx`, `admin-security.tsx`, `portal.$tenantSlug.tsx`, `shell.tsx`, plus `packages/ui/src/{tokens.css,primitives,ai,horizon,nav,overlays,data,cn}.tsx`.

**Premise correction:** no PWA layer is planned or documented for `apps/web`. "PWA," "manifest," "service worker," and "installable" do not appear anywhere in docs/02–21. The only "offline" story in the doc set is the native Expo mobile app's sync layer (`docs/08-mobile.md:13`, `docs/14-roadmap.md:67-68`, "offline outbox" as an M6 mobile deliverable). The sole web-relevant trace is docs/15's per-screen state checklist item "empty/loading/error/partial/offline/degraded-AI" (`docs/15-experience-excellence.md:125`) — a states-to-design requirement, not infrastructure, and it is not evidenced as implemented (no offline detection, no cached shell) in any sampled route. Treat every "offline" recommendation below as an interaction-design gap, not a missing service worker.

## 1. Current state, by module

**Design-system core.** Motion is entirely hand-rolled CSS: one ease (`--ease-out`) and effectively two durations (150ms for hover/focus, 250ms for entrances) — no named easing/duration scale despite docs/15 §3 specifying one. `app.css:36-39` self-documents the ceiling: *"CSS only, no animation library and no per-screen choreography. Add view transitions when a screen needs an element to fly between routes."* Confirmed by exhaustive grep: zero imports of framer-motion/react-spring/motion, zero use of `startViewTransition`/`<ViewTransition>` anywhere in `apps/web` or `packages/ui`, and neither library is even a declared dependency in either `package.json`. `.lyra-field` (app.css:44-83) gives the whole app a two-layer parallax starfield + static nebula glow keyed to dark theme only (`--star-op`/`--neb-op` are 0 in light theme, app.css:65). `.lyra-enter`/`.lyra-stagger` (app.css:85-110) key on pathname remount to replay a 6-item-max staggered rise on every navigation — a real, if modest, page-transition system, and it's reused inside a single route for step transitions (`login.tsx:413`, `key={step}` re-triggers the same rise for password→TOTP→enrol→recovery).

**Reduced motion — two independent mechanisms, one real gap.** (a) `packages/ui/src/tokens.css`'s single global `prefers-reduced-motion` media query is the only broad-spectrum override. (b) `Stat`'s live-number "twinkle" is separately gated with the Tailwind `motion-safe:` variant (`packages/ui/src/data.tsx:390`), so that specific effect degrades correctly even without the global rule. But `.lyra-field`'s drift animation, `.lyra-enter`/`.lyra-stagger`, and login.tsx's bespoke `orbit-spin` (below) all rely solely on mechanism (a); there is no component-level `motion-safe:`/JS-level `useReducedMotion` check anywhere outside `Stat`, so if the CSS override is ever bypassed (inline `style=` animations, e.g. login.tsx:329) reduced-motion users still get it.

**Broken capability found:** `packages/ui/src/overlays.tsx:21` styles the Dialog/Drawer/CommandBar scrim with `data-[state=open]:animate-in data-[state=open]:fade-in` — these are `tailwindcss-animate`/`tw-animate-css` plugin utility classes. Neither plugin is a dependency of `packages/ui` or `apps/web` (verified against both `package.json`s and grepped `tokens.css`/`app.css` for a matching `@utility` definition — none exists). This means the one deliberate entrance-animation on every modal, drawer, and the ⌘K command bar is inert: overlays currently just snap open. This is a "referenced but undefined" bug, not a design gap — worse than an unused dependency, since it looks intentional in the source.

**AXIS** (`axis-board.tsx`) — read-mostly Kanban; deliberately no drag-and-drop (lines 30-39, cards move only through their own state-machine transition + approval gate). Bilingual `LABELS` (en/ar, 97-181). Sole micro-interaction: `hover:border-accent-line` on card links (504), no explicit transition duration.

**ORBIT** (`orbit-console.tsx`) — snapshot-with-manual-refresh by design (31-35, named upgrade path to streaming). Live-number doctrine wired via `<Stat live={waitingLong > 0} />` (338), correctly using the `motion-safe`-gated twinkle above. `AgentBadge` for AI handover notes (401) flagged as English-only at the `@lyra/ui` primitive level (397-398).

**SIGNAL** (`signal-cockpit.tsx`) — `AGENT_MARK` inline for autopilot summaries (187) with `EvidenceLink` "why" affordance (241-243). **Spec gap:** docs/07 names a sankey as SIGNAL's signature money-flow visualization; the shipped surface has only `Sparkline` + `ProgressBar` + tables (249, 210-214) — no sankey exists in code.

**SCOUT** (`scout-radar.tsx`) — actually implements docs/07's quadrant-scatter signature pattern (`Quadrant`, 299-335), positioned with `insetInlineStart`/`bottom` (logical properties even inline — good discipline), dot size scaled by evidence weight, selection state lives in the URL (`?w=`, 68-71) so it survives reload/sharing. No transition on dot reposition/selection — static re-render, a motion-polish gap on the module's hero interaction.

**NORTH** (`north-brief.tsx`) — reading-column pattern (`max-w-[68ch]`, 355) per docs/07. Anomalies interrupt inline via `GuardrailNotice`, explicitly not a modal (430-432, cites CLAUDE.md rule 11 by number). Has the only `window.print()` affordance found (374). Error `Gate` rendering (327-334) does **not** surface `trace_id`.

**Admin** (`admin-security.tsx`) — deliberately read-only reporting screen (8-17); solid `Stat`/`Table`/`Badge` usage, `rowState="sealed"` pattern (413), but zero motion/animation content of any kind — admin gets no polish investment.

**Auth** (`login.tsx`) — the single most bespoke animation in the codebase: hand-built SVG `Mark()` (291-331) with `stroke-dasharray` draw-on and a continuously rotating satellite via a raw inline `style={{ animation: "orbit-spin 14s linear infinite" }}` — a one-off outside the token system, and (per the reduced-motion note above) not confirmed to respect `prefers-reduced-motion` at the component level. Explicit comment (285-287): this mark deliberately avoids the ✦ `AGENT_MARK` glyph because that symbol is reserved for AI-artifact provenance and "must not mean two things" — a precise, load-bearing ambient-AI-grammar discipline win.

**Public/marketing** (`portal.$tenantSlug.tsx`) — no session; `brandStyle(site.tenant.brand)` applied directly to `<main>` (151), confirming the 5-property tenant-brand contract reaches anonymous pages too. Native `<details>/<summary>` for progressive disclosure (186) instead of JS toggle. Zero hardcoded "LYRA."

**Design-system enforcement (positive).** `nav.tsx:4-11` hard-bans icon-only navigation via a comment stating `src/ui.test.ts` fails the build if any `label` prop ever becomes optional — a genuinely enforced (not just documented) a11y rule. `data.tsx`'s `Table` gives every table a focusable scroll region (`role="region" tabIndex={0}`, 83-87) specifically to satisfy axe's `scrollable-region-focusable`, and its `EmptyState` uses a real hand-drawn "constellation" SVG illustration (318-334) rather than a generic icon — a genuine visual-polish asset, under-leveraged (only one illustration exists for all empty states across all five modules). `cn.ts` centralizes the WCAG-required focus ring in one four-line file, so focus treatment cannot drift between components.

## 3. Prioritized recommendations (impact vs. effort — not implementation-ready)

1. **Fix the dead overlay-entrance animation (G1).** Either add the missing utility (small, low-risk) or replace with a Constellation-native CSS transition. Highest impact-per-effort item in this audit: it's a one-file bug, not a design project, and it touches every approval/consequential-action dialog in the product.
2. **Close the `trace_id` gap in error states (G6).** Two independent surfaces already violate docs/15's own checklist; likely systemic across all `Gate`/`PanelFailure` usages. Cheap to fix once, high support/trust payoff.
3. **Give SCOUT's quadrant and SIGNAL's trend surfaces a motion pass (G4/G5)** — these are each module's one bespoke, signature visual; they're also the cheapest to make feel alive (a repositioning transition, a sankey or richer flow chart) relative to their visibility in demos and daily use.
4. **Decide, deliberately, on route-transition ambition (G2/G3).** This is the one item that's a real design/spec decision, not a bugfix: either commit to the docs/15 vision (named easing scale, View Transitions between modules) and scope it as its own milestone, or explicitly de-scope it in an ADR so the current "rise + remount" approach reads as a choice, not a gap. Recommend this be the seed for the next brainstorming session, since it has the largest design surface of anything found here.
5. **Audit and standardize reduced-motion coverage (G7)** — sweep the handful of raw inline `animation` styles (starting with `login.tsx`) onto the same `motion-safe:`/token mechanism `Stat` already uses correctly, so the guarantee doesn't depend on one central CSS rule never being bypassed.
6. **Note admin's zero-polish state as intentional (G8)**, or budget a light pass if admin surfaces are ever customer-facing (some tenants may expose parts of this to their own admins).
7. **Expand the empty-state illustration set (G9)** — low urgency, but cheap panel-by-panel variation would meaningfully lift perceived craft once the higher-severity items are done.
8. **Do not build a web PWA/offline layer speculatively (G10).** Nothing in the docs asks for it; if "10/10 web UX" is meant to include installability, that needs a product decision and an ADR before any engineering, not an assumption baked into this audit's brief.
