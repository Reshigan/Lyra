# 07 — Data and Integrations

**Audience:** operations/SRE and any support engineer who has to answer "where
does this data live?" or "is that integration actually connected?"

This file is the reference for LYRA's persistence layer, its tenancy rule, its
migrations, its event bus, its API surface, its model gateway, and **every**
external service the product touches — with an honest live / stubbed / not
configured / not built verdict for each.

Read [`01-system-overview.md`](01-system-overview.md) first; this file assumes
you know what the modules are.

## 1. Database engines — one schema, two homes

| Home | Engine | Where it is configured |
|---|---|---|
| **Cloudflare (production, staging)** | **D1** — Cloudflare's managed SQLite. Bound to the API Worker as `DB` (database `lyra`; staging `lyra-staging`) | [`apps/api/wrangler.jsonc`](../../apps/api/wrangler.jsonc) |
| **On-prem / self-hosted** | **libSQL** (Turso's SQLite fork) reached over HTTP or a local file | [`packages/db/src/client-libsql.ts`](../../packages/db/src/client-libsql.ts), wired in [`apps/api/src/node.ts`](../../apps/api/src/node.ts) via `LIBSQL_URL` / `LIBSQL_AUTH_TOKEN` |
| **Local dev** | D1's local (Miniflare) SQLite file under `.wrangler/`, or a libSQL file at `file:./.data/lyra.db` | [`packages/db/drizzle.config.ts`](../../packages/db/drizzle.config.ts) |

There is exactly **one** schema for both. The ORM is **Drizzle**, pinned to the
SQLite dialect — see the comment in `drizzle.config.ts`:

```
dialect: "sqlite", // D1 (cloud) and libSQL (on-prem) share this dialect
```

**Practical consequence for support:** any SQL you write for a production
incident must run unchanged on both. No D1-only features, no Postgres syntax.
If a fix needs something SQLite cannot do, it needs a code change, not a
cleverer query.

### Cross-cutting column conventions

Every table follows these, so you can predict a table you have never seen:

| Convention | Detail |
|---|---|
| Primary keys | ULID strings in a `TEXT` column. Generated by `id()` in [`packages/db/src/ids.ts`](../../packages/db/src/ids.ts). Sortable by creation time — a higher ULID is a later row |
| Tenancy | `tenant_id TEXT NOT NULL` on every table except the two deliberate exceptions in §3 |
| Timestamps | `created_at` / `updated_at` as **epoch milliseconds integers**, UTC. Not ISO strings, not seconds |
| Soft delete | `deleted_at` (epoch ms, null when live) where a table supports deletion. Six resources are delete-exempt by design — see ADR-0013 |
| Money | Integer **minor units** (`*_minor`) plus a separate `currency` column. Never floats, never a decimal type |
| Rates | Parts-per-million (`ppm`) integers. 12.5% is `125_000` |
| JSON columns | Stored as `TEXT`, shape-validated by zod schemas in [`packages/db/src/json.ts`](../../packages/db/src/json.ts). Column names end in `Json` in TypeScript, `_json` on the wire |

## 3. The tenancy rule, and how it is actually enforced

**The rule ([`CLAUDE.md`](../../CLAUDE.md) convention 1):** every table carries
`tenant_id`, and no query may cross tenants.

**The important correction:** `CLAUDE.md` and several documents in
[`docs/`](../) refer to a helper called **`withTenant(db, tenantId)`. That
function does not exist in the code.** The real enforcement lives in
[`packages/core/src/context.ts`](../../packages/core/src/context.ts) and has
three parts:

| Helper | What it does |
|---|---|
| `scoped(ctx, table, ...extra)` | Builds the `WHERE`. Always adds `tenant_id = ctx.tenantId`, and adds `deleted_at IS NULL` automatically when the table has that column. **The only sanctioned way to build a where-clause on a tenant-scoped table.** Used in ~146 places |
| `scopedWithDeleted(ctx, table, ...extra)` | Same tenant filter, without the soft-delete filter. For restore flows, audit exports and DSARs |
| `assertTenant(ctx, row, resource)` | Runtime backstop for a row that arrived from anywhere other than `scoped()`. A cross-tenant row is thrown as **not found**, never forbidden — "forbidden" would confirm the row exists |

Two details worth knowing during an incident:

1. A table with neither `tenant_id` nor `id` **throws** rather than producing an
   unfiltered `WHERE`. `core_tenants` is scoped by its own `id`, because the row
   *is* the tenant.
2. `Ctx` (built once per request by the gateway) is the only thing a handler is
   allowed to know: `db`, `tenantId`, `actor`, `requestId`, `now`, `locale`,
   `policy`, `entitlements`, `ip`, `ua`. `now` is a single request-start clock so
   every row written by one request shares a timestamp.

**Deliberate exceptions** (both recorded, both platform-global with no
`tenant_id`): `core_feature_flags` (ADR-0028 — flags must exist before any
tenant does), and the platform-staff tables `core_slo_definitions` /
`core_deployments` (ADR-0029). Cross-tenant *reads* by platform staff are done
as a loop over active tenants, one scoped context each — never one unfiltered
query. There is no cross-tenant **write** primitive (ADR-0029 defers it).

here: **a schema change cannot be rolled back by redeploying the previous
Worker.** Code rolls back; migrations do not.

## 5. The event bus

**Topic:** a single Cloudflare Queue named `lyra-events`. The API Worker is both
producer (binding `EVENTS`) and consumer (`max_batch_size: 25`).

**Envelope** ([`docs/04-api.md`](../04-api.md) §7, enforced by the `Envelope`
zod schema in [`packages/core/src/events.ts`](../../packages/core/src/events.ts)):

```
{ id, ts, tenant_id, module, type, actor, subject, data, v: 1 }
```

**The path a domain event takes:**

1. `emit(ctx, input)` writes a row to `core_event_outbox` **inside the same
   database transaction as the state change it describes**. That is the entire
   point of the outbox — an event cannot exist for a change that rolled back.
2. The cron tick calls `drainOutbox(ctx, env.EVENTS)`, which reads
   `pendingOutbox()` (oldest-first, batch-limited) and publishes to the queue.
   Rows that failed `MAX_ATTEMPTS` (**5**) times are dead-lettered *first*, so a
   head of poison rows cannot starve every newer event.
3. The Worker's `queue()` handler delivers each message. A message that keeps
   failing past `MAX_QUEUE_ATTEMPTS` is acked and logged rather than blocking its
   batch slot forever.
4. Consumers run through `consume()`, which records `(event_id, consumer)` in
   `core_event_inbox` — that composite key is what makes a handler exactly-once.
   Terminal failures land in `core_event_dlq`, **visibly, never silently dropped**.
5. `replayDlq()` clears the inbox marker so an admin can re-run the handler.
   `pruneOutbox()` deletes published rows past a cutoff.

**Event catalogue** (the same types are used for outbound webhooks) — from
`docs/04-api.md` §7: `core.customer.created|updated|erased`,
`core.consent.updated`, `axis.case.created|status_changed`,
`axis.document.extracted`, `axis.quote.added`, `axis.policy.issued`,
`axis.approval.requested|decided`, `orbit.conversation.started|handover|closed`,
`orbit.renewal.due|offered|accepted|lost`, `orbit.partner.txn`,
`signal.campaign.launched|paused`, `signal.experiment.concluded`,
`signal.budget.moved`, `signal.creative.flagged`, `scout.whitespace.promoted`,
`scout.bench.updated`, `north.anomaly.detected`, `north.briefing.published`,
`ai.budget.threshold`, `platform.key.rotated`.

**Modules may not import each other.** Cross-module integration is events only;
the sole permitted direct import is from `packages/core`.

|---|---|
| Base URL | `https://api.lyra.vantax.co.za/v1` (cloud). On-prem: `https://{host}/api/v1` |
| Framework | Hono, in [`apps/api`](../../apps/api). Module routers mounted under `/v1/{module}` |
| Wire format | JSON only, `snake_case`, ULIDs, money as integer minor units + `currency`, times as epoch ms UTC, locales BCP-47 |
| Errors | RFC 9457 `problem+json`: `{type, title, status, detail, trace_id}` |
| Pagination | Cursor: `?cursor=&limit=` (max 100). Filtering RSQL-lite (`?filter=status==active;line==motor`). Sparse fields `?fields=` |
| Idempotency | `Idempotency-Key` header honoured on **all** POSTs for 24h, backed by `core_idempotency_keys` |
| Versioning | URL major (`/v1`). Additive changes are free; breaking changes go to `/v2` with a 12-month sunset |
| Rate limits | Per key: interactive 60 rpm, server 600 rpm, burst ×2. Enforced by the `RateCounter` Durable Object. `429` with `Retry-After`. AI endpoints are additionally metered in tokens |
| Auth — users | Session in an HTTP-only cookie. SSO via OIDC. MFA (TOTP) for staff roles |
| Auth — machines | API keys `qvk_live_…` / `qvk_test_…`, hashed at rest with prefix lookup, scoped to tenant + module + permissions |
| AuthZ | Permission strings `module:resource:action` (e.g. `axis:cases:approve`). Every check goes through `can(actor, perm, subject)` in [`packages/core/src/rbac.ts`](../../packages/core/src/rbac.ts) — no ad-hoc checks |
| Webhooks out | HMAC-SHA256 `Lyra-Signature: t=..,v1=..`; 8 retries, exponential, ≤24h; per-endpoint secret; delivery log queryable; replay from admin |

**Where OpenAPI lives:** the spec is **generated from the zod route schemas**,
not hand-written. The generator is
[`apps/api/src/openapi.ts`](../../apps/api/src/openapi.ts); the build script is
[`packages/sdk/scripts/generate.ts`](../../packages/sdk/scripts/generate.ts), and
the output lands in [`packages/sdk/src/generated.ts`](../../packages/sdk/src/generated.ts)
alongside the hand-written [`client.ts`](../../packages/sdk/src/client.ts) and
[`webhooks.ts`](../../packages/sdk/src/webhooks.ts). If a route's zod schema
changes, regenerate the SDK — the contract tests will otherwise fail.

Surface map by module is in [`docs/04-api.md`](../04-api.md) §4.

## 7. Scheduled jobs

One Cloudflare cron trigger drives everything: `*/5 * * * *` in production,
`*/15` on staging. The handler is `scheduled()` in
[`apps/api/src/index.ts`](../../apps/api/src/index.ts). On-prem, the same work is
driven by a `CRON_INTERVAL_MS` timer in [`apps/api/src/node.ts`](../../apps/api/src/node.ts).

**Every tick, platform-wide:** `pruneSessions`, `pruneIdempotency`.

**Every tick, per tenant** (each tenant in a `try` so one bad tenant cannot
starve the fleet):

| Order | Job | What it does |
|---:|---|---|
| 1 | `drainOutbox` | Publishes pending outbox rows to `lyra-events` |
| 2 | `sweepPolicyLifecycle` | Starts, lapses and ends cover on the clock. Runs **before** renewals so an expiring policy is in the right state |
| 3 | `sweepRenewals` | Creates/advances renewal rows; hands long work to the `RenewalWorkflow` |
| 4 | `sweepRouting` | Escalates conversations that missed their SLA clock and requeues those whose agent went quiet |
| 5 | `runBudgetAutopilot` | SIGNAL budget moves within bounds |
| 6 | `runDueSchedules` | Renders and delivers due analytics schedules (uses R2 `FILES` and Browser Rendering) |
| 7 | `expireDelegations` | Retires delegations past their window, so admin screens stop lying about who holds authority |
| 8 | `sweepConversationDrafts` | Drafts the next reply for every conversation waiting on us. **Draft only — nothing is sent without a human** |

**Nightly, gated on UTC 02:00–02:15** (there is no second cron; the jobs check
the hour themselves): `backupTenant` (D1 → R2 `EXPORTS`), `anchorAudit`
(hash-chain tamper evidence pinned outside D1 — a break is logged as
`audit chain broken` and **nothing in the system can repair it**),
`nudgeApiKeyRotation`, `runSnapshotter` (NORTH nightly metrics).

Sweeps take a bounded bite per tick (`SWEEP_MAX`) — ADR-0050, which also records
the one sweep that is still uncapped.

## 8. The model gateway

**Rule:** no app code ever calls a provider SDK. Everything goes through
[`packages/model-gateway`](../../packages/model-gateway), which exposes a single
`complete(req: ModelRequest)`. Callers ask for a **tier** — `fast`, `standard`,
`reasoning` — never a model name.

**Routing table** ([`packages/model-gateway/src/models.ts`](../../packages/model-gateway/src/models.ts)):

| Tier | Cloud default | On-prem |
|---|---|---|
| `fast` | `llama-3.1-8b` (Workers AI, `@cf/meta/llama-3.1-8b-instruct-fast`) | `internal-chat` (whatever vLLM serves) |
| `standard` | `llama-3.3-70b` (`@cf/meta/llama-3.3-70b-instruct-fp8-fast`) | `internal-chat` |
| `reasoning` | `llama-3.3-70b` | `internal-chat` |
| embeddings | `bge-m3` (`@cf/baai/bge-m3`) | `internal-embed` |

Also in the catalogue but **not routed to by default**: `claude-opus-5`,
`claude-sonnet-5`, `claude-haiku-4-5` (Anthropic). They are reachable only via a
tenant tier-override or an explicit `modelKey` — and today only by AXIS vision
extraction, which pins `claude-haiku-4-5` (ADR-0036).

Three routing rules you need when a ticket says "the AI picked the wrong model":

1. **Data residency wins over tenant overrides.** If the tenant's
   `policy_json.dataResidency === "on-prem"`, every tier is pinned to
   `openai-compat` even if an override names a cloud model. A cloud override on
   an on-prem tenant is a residency breach, so the pin wins.
2. **An unknown override key is ignored, not obeyed.**
3. **Tool support is never silently dropped.** If the request carries tools and
   the routed model has none, the gateway upgrades to a tool-capable model *from
   the same provider* and lets the cost land.

**Providers** ([`packages/model-gateway/src/providers/`](../../packages/model-gateway/src/providers)):
`workers-ai.ts`, `anthropic.ts`, `openai-compat.ts` (vLLM/Ollama), `stub.ts`
(deterministic fixtures for tests and `qvk_test_` keys).

**`ai_audit_log` is written for every call, without exception.** Each row carries
tenant, module, purpose, actor, subject, model, provider, tier, input/output
hashes (not the text), token counts, `cost_micro` (micro-USD, always rounded up
so a tenant is never under-billed against its budget), latency, tool calls,
guardrail flags, and an outcome of `ok`, `refused`, `error`, `budget_exceeded`
or `killed`. Retention is 7 years, and the log is exportable. If a call does not
appear here, it did not go through the gateway — that is a bug, not a gap.

Other gateway modules worth knowing by name: `budget.ts` (per-tenant-per-day
caps), `guardrails.ts` and `scrub.ts` (PII and injection defences), `kill.ts`
(the platform-wide agent pause), and the purpose registry in `purposes.ts`.
Evals live in [`packages/model-gateway/evals/`](../../packages/model-gateway/evals)
and are run as tests.

## 9. External integrations — what is actually connected

This is the section to read before promising a customer that something works.
Four honest states are used:

- **LIVE** — code exists, is configured, and runs in production today.
- **STUBBED** — code exists and runs, but returns synthetic results by design. A
  real provider is a configuration-plus-adapter job.
- **NOT CONFIGURED** — the code is complete and would work, but no credential,
  connector row or resource has been created. It does nothing today.
- **NOT BUILT** — there is no code. The name may appear in a spec, a comment or
  an unbuilt `switch` branch.

## 10. Secrets — names only

**No secret value appears anywhere in this pack, in the repository, or in the
database.** Secrets are set with `wrangler secret put` (cloud) or Docker env
(on-prem). `core_identity_providers.client_secret_ref` stores the *name* of a
secret, never its value.

The names that exist, so you can tell "unset" from "wrong":

| Surface | Names |
|---|---|
| API Worker ([`apps/api/src/env.ts`](../../apps/api/src/env.ts)) | `ANTHROPIC_API_KEY`, `OPENAI_COMPAT_URL`, `OPENAI_COMPAT_API_KEY`, `AI_GATEWAY_URL`, `FIELD_KEY`, `TURNSTILE_SECRET`, plus the plain vars `APP_ORIGIN`, `ENVIRONMENT`, `SESSION_COOKIE` |
| Web Worker | `ENVIRONMENT`, `API_ORIGIN`, `SESSION_COOKIE`, `TURNSTILE_SITE_KEY` (read but undeclared — see §9.5) |
| On-prem / Node | `LIBSQL_URL`, `LIBSQL_AUTH_TOKEN`, `DATABASE_URL`, `DATABASE_AUTH_TOKEN`, `FILES_DIR`, `PORT`, `RUNTIME`, `MODE`, `CRON_INTERVAL_MS`, `SEED_PASSWORD` |
| CI / evals | `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `CF_ACCOUNT_ID`, `CF_API_TOKEN`, `CF_AI_TOKEN`, `LYRA_EVAL_LIVE`, `GITHUB_TOKEN`, `GITLEAKS_LICENSE` |
| Mobile | `EXPO_PUBLIC_API_URL` |

`FIELD_KEY` deserves a warning: it is the AES-256-GCM key for field-level
encryption ([`packages/core/src/field-crypto.ts`](../../packages/core/src/field-crypto.ts)).
**Key rotation was never built (ADR-0032).** Once real encrypted data exists,
changing `FIELD_KEY` makes that data unreadable. Do not rotate it without a
migration plan.

## 11. Quick answers

| Question | Answer |
|---|---|
| "Where is customer X's data?" | `core_customers` is the spine; everything else joins on `customer_id` within the same `tenant_id` |
| "Can I run this SQL on production?" | Only if it works on both D1 and libSQL, and only with an explicit `tenant_id` predicate |
| "Why didn't the webhook fire?" | Check `core_event_outbox` (unpublished?), then `core_event_dlq`, then `core_webhook_deliveries` |
| "Why is the AI not responding?" | Check `ai_audit_log` for the call. Outcome `budget_exceeded` → `ai_budgets`. Outcome `refused` → `ai_guardrail_events`. No row at all → the call never reached the gateway |
| "Did we send that WhatsApp?" | No. The channel is not configured (§9.3) |
| "Where did the payment go?" | Nowhere through LYRA — there is no PSP. `ledger_payments` / `ledger_settlements` record money moved elsewhere (§9.4) |
| "Why does the report show a stale number?" | NORTH reads `north_snapshots`, refreshed nightly at 02:00 UTC (§7), not live tables |
